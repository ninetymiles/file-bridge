# 元数据存储

## 位置与运行模式

索引数据库位于 `OUTPUT_DIR/metadata.sqlite`，使用 SQLite 的 WAL 模式。

## 索引表结构

表 `file_metadata` 字段：

| 字段 | 说明 |
|---|---|
| `sender_id` | 发送者标识，必填 |
| `sender_nick` | 发送者昵称，可空 |
| `created_at` | 接收时间，格式 `YYYY-MM-DD HH:MM:SS`，服务器本地时间 |
| `original_filename` | 原始文件名 |
| `saved_path` | 本地保存路径 |
| `sha256` | 文件内容哈希，用于去重 |
| `file_size` | 文件大小 |
| `media_type` | 媒体类型，可空 |

`media_type` 取值：

- `picture`：照片，包含 `richText` 中的图片段。
- `video`：视频。
- `file`：其他文件。

该列不设默认值与约束，旧版本服务不认识该列时仍可正常插入，写入行的值为空。

## schema 版本校验

数据库通过 `PRAGMA user_version` 记录结构版本，当前版本为 1。

启动时的行为：

- 库文件不存在：创建当前结构并写入版本 1，建表与版本写入在同一事务内完成。
- 库文件存在且版本为 1：只读校验，正常启动。
- 库文件存在但版本为 0（旧库、空文件或建库中断残留）：抛出显式错误并拒绝启动，不修改数据库。
- 库版本高于 1：抛出显式错误并拒绝启动，不做降级。

系统不提供旧结构自动升级。

## 部署要求

从没有 schema 版本的旧版本升级时，必须在部署阶段人工删除旧库：

1. 停止服务。
2. 备份或删除 `metadata.sqlite` 及同目录的 `-wal`、`-shm` 文件。
3. 启动服务，首次启动会创建当前结构并写入版本 1。

删除旧库会丢失索引中的发送者/原始文件名映射与 SHA-256 去重历史。磁盘上的媒体文件仍保留，但重建索引只清理缺失记录、不扫描磁盘补录，统计报告会从空状态开始，直到有新投稿。

## 兼容性

`media_type` 为可空列，发布前的旧版本服务可以连接版本 1 的库并正常运行，其新写入记录的媒体类型为空，由统计报告按扩展名回退归类。任何后续把该列改为非空、改名或删除的迁移都会破坏这一兼容性。
