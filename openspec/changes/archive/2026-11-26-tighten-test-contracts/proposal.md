# Proposal

## Why

现有单元测试把「日志内容、日志级别、日志顺序」当作契约反复断言，既违反项目禁用的「用诊断日志做断言」，也把实现细节固化成了不可演进的天条；另有一批规格（`runtime-logging`、`photo-review` 的健康报告、`storage-warmup` 的日志级别）本身只是在描述实现约束，却迫使测试去核验这些约束，属于过度测试。

## What Changes

- 测试侧：
  - 删除所有 `caplog` 断言与相关夹具；日志不再是任何用例的判据。
  - 能替换为行为判据的改成类型 / 数量 / 对象存在性 / 外部调用次数断言。
  - 保留每个叶子接口的行为契约（调用一次、返回值、抛错、字段内容、取消动作），维持「叶子 → 支路 → 主干」的失败定位链，不把复杂度推给集成测试。
- 规格侧：
  - `runtime-logging` 能力整体下线。
  - 新建 `log-redaction`：只记录「凭证不得进入日志」这一实现要求，**不建自动化测试**。
  - `photo-review`：删除「启动健康报告」要求；健康探测与总时限要求只保留行为，删除日志级别与文本表述。
  - `storage-warmup`：删除 ERROR/WARNING 级别与「首条日志」表述，顺序要求改写为「预热先于处理链」；新增「唤醒提示的发送路径不含本地 I/O」，用规格与注释记录、不建测试。
- 明确非目标：不修改业务逻辑（仅在关键路径补充约束注释）；不处理 C 类白盒测试（另行分析）；不新增日志功能。

## Capabilities

### New Capabilities

- `log-redaction`: 记录日志脱敏的实现要求（凭证、令牌、下载码不得进入日志），仅作实现与评审核验依据，不含自动化测试。

### Modified Capabilities

- `photo-review`: 健康探测与总时限要求去掉日志级别/文本表述，只保留启用、禁用、取消等行为。
- `storage-warmup`: 预热异常与 LLM 预热要求去掉日志级别表述；「探针先于首条日志」改写为「预热先于处理链」。
- `runtime-logging`: 整能力删除。

## Impact

- `tests/`：9 个测试文件删除或改造约 25 个用例，删除 8 个日志辅助函数/夹具。
- `openspec/specs/`：1 个能力删除、1 个能力新建、2 个能力裁剪。
- `app/handlers/message.py`、`app/services/disk_warmup.py`：仅补充顺序约束注释，无逻辑变更。
- `docs/storage.md`：冷盘小节补一句日志顺序说明。
- 无配置、无数据变更。
- 明确放弃的自动化覆盖：日志级别边界、连接结论行、httpx 抑制、启动/接收摘要文本、凭证脱敏；这些改由变更 `design.md` 记录并在实现评审中检查。
