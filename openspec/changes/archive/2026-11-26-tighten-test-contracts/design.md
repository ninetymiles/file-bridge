# Design

## Context

动机见 [proposal.md](proposal.md) - "Why"。

约束：

- 本地编码准则禁止把诊断日志作为功能测试判据；契约测试只验证行为。
- `runtime-logging` 把日志文本、级别、顺序写成了能力要求，导致测试只能断言 `caplog`。
- 测试架构要求「叶子 → 支路 → 主干」的失败定位链：单点接口要有独立的叶子用例，不能把全部契约塞进集成测试。
- 生产代码不需要任何改动；本变更只动 `tests/` 与 `openspec/specs/`。

## Goals / Non-Goals

**Goals:**

- 测试中不再出现 `caplog` 与日志辅助夹具。
- 每个叶子接口保留行为断言，删除后不把该行为推给集成测试。
- 规格只保留可验证行为；实现约束集中记录。

**Non-Goals:**

- 不修改生产代码、配置、数据库。
- 不处理 C 类白盒问题（mock 协作者、私有函数/属性、模块内 patch），另行变更。
- 不新增任何日志能力。

## Decisions

### D1：日志整体退出契约，实现约定集中记录

删除 `runtime-logging` 能力，其内容不再作为规格或测试判据。以下约定保留为长期实现要求，只记录在本文件「实现约定」一节（不新增文档）：

- INFO 只承载接收摘要、下载开始、保存成功、回复结果、启动摘要与连接结论；DEBUG 承载 downloadCode、临时 URL、原始报文。
- 发送动作先于本地日志写入（冷盘下避免日志 I/O 延后用户提示）。
- httpx 逐请求 INFO 行保持抑制。
- 连接日志只输出结论行，不输出 endpoint/ticket。
- 健康探测与 LLM 预热只输出单行报告/单行 WARNING，成功预热不占 INFO。

备选方案：保留规格但标注「不可测」→ 否决，规格中存在无法验证的要求会持续诱发过度测试。

### D2：脱敏单独记录，不建测试

新建 `log-redaction`，只写「凭证、令牌、下载码、签名 URL 不得进入日志」。该要求由实现评审确认，不建立自动化用例——它在观察手段上只能用日志核验，与「日志不作为测试判据」冲突。

### D3：顺序不变量只保留集成级验证

单元级的「发送先于日志」「预热先于首条 INFO」删除；集成级用例改为观察「唤醒提示发出 → 探针完成 → 最终回复」的事件序列，事件来自探针回调与回复捕获，不读日志。`storage-warmup` 中「探针先于首条日志」改写为「预热先于处理链」。

**配套记录（防止未来静默破坏）**。删掉断言后，顺序约束必须留在可被发现的位置：

| 落点 | 现状 | 需要补充 |
|---|---|---|
| `storage-warmup` 规格 | 只写「立即回复唤醒提示」，未提日志顺序 | 新增要求「唤醒提示的发送路径不含本地 I/O」，标注由评审保证、不建测试 |
| `PipelineHandler.async_reply_text` | 已有 docstring 说明「先发送、后记录」，并解释冷盘原因 | 保留，补一句「禁止把日志移到发送之前」的显式禁令 |
| `PipelineHandler._dispatch` 的 `on_waking` | 注释只说明「不等待模型预热」 | 补一句：该回调内的用户可见发送必须先于任何本地日志写入 |
| `ensure_storage_ready` | docstring 说明计时与探针的竞争 | 补一句：`on_waking` 必须先完成用户可见发送，再做本地记录 |
| `docs/storage.md` 冷盘小节 | 只写「先回复，不等待探针结束」 | 补一句：本地日志记录在发送完成之后，避免冷盘 I/O 延后提示 |

### D4：叶子契约保留清单

删除日志断言后，以下叶子判据必须仍在单测中（这是失败定位链的叶子）：

| 叶子 | 判据 |
|---|---|
| 启动索引检查 | `rebuild_index` 调用一次 |
| 日志级别配置 | `setup_logger` 返回的记录器级别为 INFO |
| 下载器 | 返回 URL、抛错、`sha256`/`file_size`/落盘内容 |
| 媒体处理器 | 下载接口调用次数 = 图片数；回复意图文本与层级 |
| 点评探测 | `ready`/`status`/`reachable`/`models`/`model_present` |
| 点评总时限 | 取消动作发生、未完成点评不进入回复 |
| 命令匹配工厂 | 返回的匹配器类型、构造失败抛错 |

### D5：取消动作作为契约

点评超时用例改为由假 reviewer 捕获 `CancelledError` 并置事件；断言「取消事件已发生」与「回复数量不变」，不断言日志。

### D6：语义匹配工厂用例本轮删除

去掉日志断言后，该用例只剩对伪造类的 `isinstance` 判断，属白盒；本轮直接删除，等 C 类用公开注入点重写后再补。

### D7：夹具随用例一并清理

`_wait_for_log`、`_EventLogHandler`、`_ReceivedLogHandler`、`_attach_received_log`、`_detach_received_log`、`configured_logs`、`_make_stream_record`、`_emit` 全部删除；不保留无使用者的辅助函数。

## 实现约定（长期有效，无自动化核验）

1. 日志级别边界：INFO 不含 downloadCode、临时下载 URL、访问令牌、回调报文头、原始 payload；这些只在 DEBUG 出现。
2. 回复发送先于本地 INFO 写入；发送失败记 WARNING。
3. 启动输出一次版本与配置摘要（不含 `client_secret`），连接建立输出「已连接」结论行，收到 disconnect 输出「已断开」结论行。
4. httpx 的逐请求 INFO 行维持在 WARNING 阈值以上才输出。
5. 图片/文件下载码、签名 URL、API Key 明文不得进入任何级别日志；令牌只以脱敏指纹呈现。
6. 健康探测输出单行报告（地址、模型、数量、是否命中、密钥掩码），成功 INFO、失败 WARNING。
7. LLM 预热失败只输出单行 WARNING，成功不占 INFO。
8. 接收摘要携带可读正文（`text` 为原文，`richText` 为合并文本并以 `<imgN>` 表示图片段）。

## Risks / Trade-offs

- [日志噪音治理（filter、httpx 抑制）失去自动化保护] → 该类改动很少发生；漏改的后果只是日志变吵，不影响业务；由评审把关。
- [凭证脱敏失去自动化保护] → 属于安全底线，评审清单需显式包含「新增日志是否输出敏感值」。
- [删除日志断言后，若实现真的改坏了日志，无人发现] → 接受：日志不是对外契约。
- [C 类白盒问题仍在，语义工厂用例暂时缺覆盖] → 记录在 proposal 的「非目标」，由后续变更补齐。

## Migration Plan

- 无生产变更，测试与规格一次性调整。
- 回滚：还原测试与规格文件即可，无残留状态。
- 验证：`uv run pytest` 全绿；`openspec validate --strict` 通过。
