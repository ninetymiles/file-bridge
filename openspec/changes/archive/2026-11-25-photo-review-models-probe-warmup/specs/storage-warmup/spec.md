# Spec Delta

## ADDED Requirements

### Requirement: 冷盘唤醒期间的 LLM 预热

当消息入口的存储预热因冷盘超过 3 秒、且启动健康检测已确认 API 可达并包含配置模型时，系统 SHALL 在发送唤醒提示的同时，以 fire-and-forget 方式向点评网关发起一次文本 chat 请求，输出 token 上限 SHALL 为 1，以提前触发模型加载。该请求 MUST NOT 被等待完成后再发送唤醒提示或继续等待磁盘；MUST NOT 参与点评启用或禁用决策；失败时 SHALL 只输出单行 WARNING，成功时 SHALL NOT 在 INFO 级别输出。并发冷盘消息产生的重复请求 SHALL 通过 in-flight 去重限制为至多一个未完成请求。启动健康检测未通过或点评未启用时 MUST NOT 发起该请求。

#### Scenario: 冷盘唤醒时并发触发模型加载

- **WHEN** 存储探针在 3 秒内未完成，且启动健康检测已通过
- **THEN** 系统在发送“正在唤醒存储服务”提示的同时发起一次 LLM 预热请求，唤醒提示不被该请求延迟，磁盘等待继续正常进行

#### Scenario: 热盘快速就绪时不预热

- **WHEN** 存储探针在 3 秒内完成
- **THEN** 系统不发送唤醒提示，也不发起 LLM 预热请求

#### Scenario: 预热失败只记录诊断日志

- **WHEN** LLM 预热请求返回非 2xx、超时或网络异常
- **THEN** 系统只输出一行 WARNING，点评能力保持原启用状态，磁盘等待与后续消息处理不受影响

#### Scenario: 健康检测未通过时不预热

- **WHEN** 启动健康检测失败（API 不可达或配置模型不在清单中）
- **THEN** 冷盘唤醒时系统只发送唤醒提示，不发起 LLM 预热请求

#### Scenario: 并发冷盘消息不重复加载

- **WHEN** 同一冷盘唤醒期间有多条消息同时进入处理链
- **THEN** 至多存在一个未完成的 LLM 预热请求，后续消息不会叠加新的预热请求
