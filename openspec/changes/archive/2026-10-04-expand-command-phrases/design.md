# Design: expand-command-phrases

## Context

`rebuild_index` 的真实职责是校验元数据记录与磁盘文件的一致性并清理缺失记录（不扫描文件系统、不补录新文件），该语义基准由前置变更 `clarify-rebuild-index-semantics` 确立。当前子串匹配器与语义匹配器共用同一份 `COMMAND_CATALOG`：同一条短语既是子串模式的字面触发词，又是语义模式的 embedding 锚点。本变更在此约束下扩充 `rebuild_index` 的触发短语。

## Goals / Non-Goals

**Goals:**
- 围绕"校验/同步/清理"语义扩充 `rebuild_index` 触发短语，提升口语化表达的召回率。
- 不破坏现有负样本（状态询问、无关文本）的拦截能力。

**Non-Goals:**
- 不修改匹配器架构、匹配阈值（0.8）、模型、归一化逻辑、命令 id 或命令回调。
- 不引入"语义专属短语"分组；不纳入"生成索引""重新生成索引"等暗示补录语义的短语。
- 不新增第二个命令（如独立的状态查询命令）。

## Decisions

### D1: 沿用共用目录，不拆分语义专属短语
同一条短语同时驱动子串与语义两个匹配器。备选方案是把目录改为每个命令两组短语（字面组 + 语义锚点组），从而允许加入"裸动词/症状驱动"等在子串模式下不安全、但可作语义锚点的短语。该方案需改动 catalog 数据结构与两个匹配器，属于架构变更。考虑到本次扩充的候选词均为完整动宾结构（在子串模式下本就安全），拆分带来的收益不抵复杂度，故沿用共用目录，仅做数据扩充。

### D2: 选词以职责语义为边界，排除"生成"类
依据 `rebuild_index` 的真实职责（只清理、不补录），"生成索引""重新生成索引"暗示了实现中不存在的"扫描磁盘补录新文件"语义，纳入会误导用户对命令行为的预期，故排除。"检查/校验/同步/刷新/更新"类动词与"一致性校验"语义一致，予以纳入。

### D3: 状态询问误命中通过疑问句拦截规则解决（机制层）
原假设是"越线就剔除该短语"（数据层裁剪）。语义实测证伪了该假设：bge-small-zh 是词向量模型，对"了吗/完成了吗/好了吗"等疑问后缀几乎不敏感，导致"更新索引了吗"（0.9094）比部分正样本得分更高；任何含"索引"的询问句都会越过 0.8 阈值，无论目录放什么短语。这是 embedding 单点匹配的固有边界，剔除短语无法解决（询问句会撞到剩余短语上）。

因此改为在匹配前增加一道**疑问句拦截规则**：归一化后、送入匹配器前，若文本以疑问/询问语气结尾（如"了吗""完成了吗""好了吗""怎么样""多少""吗"），系统直接判定无命中，不调用匹配器（语义模式不触发模型推理）。该规则对子串与语义两个匹配器统一生效，置于归一化之后以保持单一入口。疑问语气模式集合为代码内固定常量，不通过环境变量配置。备选方案（提高阈值）被否决：能压住 0.9094 的阈值会同时压掉得分偏低的口语正样本。

## Risks / Trade-offs

- [疑问句拦截规则误伤合法命令] → 合法命令极少以疑问语气结尾；拦截模式仅覆盖明确的疑问/询问后缀，不影响陈述式命令。
- [疑问模式集合覆盖不全，新型询问表达漏拦截] → 拦截是best-effort减负，模式集合可在后续按需扩充；残余高重叠询问仍可能误命中，属可接受边界。
- [共用目录下短词/泛词在子串模式误伤] → 只纳入完整动宾结构短语，排除裸动词与裸宾语。
