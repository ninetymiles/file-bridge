# Proposal

## Why

一条 `richText` 消息携带多张图片时，系统当前会对每张保存成功的图片各发一次点评请求，再把结果拼成「图1：…」「图2：…」的长回复。用户只需要一条简短点评，多图逐张点评既增加网关负载，也让回复变得冗长。

## What Changes

- 多图消息只产生**一条**点评：按图片段原始顺序点评**第一张保存成功的图片**；重复图片与保存失败的图片自动跳过、不消耗这次点评机会。若该次点评未取得有效文本，本条消息就不产生点评，**不重试、不顺延**。
- 选择不依赖任何额外等待：处理到第一张保存成功的图片时立即起跑点评，与该图之后图片的下载并行进行。
- 点评文本的图号规则改为按消息图片段判定：消息含多个图片段时，唯一一条点评必须以「图N：」标明是对第几张图（N 为图片段原始序号，含重复与失败的图片段）；消息只含一个图片段时保持无编号。
- **BREAKING**：取消「多图点评合并为一条分段消息」形态，以及「单张点评不加图号」在多图消息中的适用性；相关既有场景与测试需改写。
- 保留既有的两段式投递机制：15 秒合并窗口内取得点评则并入首次回复，窗口外则先发保存结果、再以「照片点评：」补发，单条消息回复总数仍不超过 2 条。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `message-pipeline`: 「照片点评两段式回复」要求改为“只点评第一张保存成功的图片、失败即无点评、多图消息必带图号”；删除多图逐张分段点评的既有场景。
- `photo-review`: 「点评请求总时限」中“群聊多图共享一个总时限”的场景改为“一条消息至多一个点评请求，总时限只约束该请求”，并明确不重试、不顺延。

## Impact

- `app/handlers/message.py`：`MediaFileHandler._handle_rich_text` 只在第一张图片保存成功时 `batch.add`；`_format_reviews` 的编号判定改为依据图片段数量。
- `tests/test_media_review_reply.py`：多图点评用例改为“单次请求 + 图号 + 重复图自动跳过”，保持确定性、无需注入随机源。
- `openspec/specs/message-pipeline/spec.md`、`openspec/specs/photo-review/spec.md`：按上述 delta 更新。
- 不变：点评服务本身、启动探测、冷盘唤醒与模型预热、15 秒窗口、60 秒总时限、回复数量上限。
