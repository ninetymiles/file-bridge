# Proposal

## Why

用户以"清理索引"表达索引一致性校验意图时未触发任何命令。实测该文本与全部锚点的最高余弦相似度为 0.7975（命中最近的"检查索引"），仅低于固定阈值 0.8 约 0.0025。根因是命令目录缺少"清理"语义族的锚点，而非阈值偏高：把输入语义域内的锚点补上即可命中，且不影响负样本。

## What Changes

- 在 `rebuild_index` 触发短语组新增 `清理索引`。目录由子串匹配器与语义匹配器共用，因此该短语同时成为语义锚点与字面触发词。
- 依据实测，单个锚点即可覆盖整个"清理"语义族：`索引清理` 0.9823、`清除索引` 0.9197、`帮我清理索引` 0.9209、`清理一下索引` 0.9263、`清理失效索引` 0.9100、`把索引清理干净` 0.9005、`清理文件索引` 0.8942、`清理索引数据` 0.8900、`清理无效索引` 0.8822。
- 负样本不受影响：`索引是什么` 0.7814、`索引在哪里` 0.7705，仍低于阈值。
- **不修改**匹配阈值（0.8）、embedding 模型（`BAAI/bge-small-zh-v1.5`）、匹配器实现、文本归一化与疑问句拦截规则。
- 在 design 中记录扩容取舍准则：补齐缺失的语义族优先于增加同族变体（同族变体对 `max` 相似度几乎没有边际收益）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `semantic-command`: `rebuild_index` 触发短语的覆盖范围新增"清理"语义族；并在规范中记录"补新语义族优先于补同族变体"的扩词准则。

## Impact

- 代码：`app/services/command_matching/catalog.py`（仅新增一条短语数据，无逻辑改动）
- 测试：`tests/test_command_matching.py`（子串断言）、`tests/test_semantic_command_smoke.py`（真模型正样本）
- 规范：`openspec/specs/semantic-command/spec.md`（增量）
- API / 依赖 / 系统：无
