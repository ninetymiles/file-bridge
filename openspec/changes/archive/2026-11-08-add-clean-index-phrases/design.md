# Design

## Context

命令匹配目录 `COMMAND_CATALOG` 同时驱动子串匹配器与语义匹配器；语义匹配器以固定阈值 0.8 对全部短语取最大余弦相似度（见 proposal.md - Why）。当前 `rebuild_index` 短语组缺少"清理"语义族，"清理索引"的最高分为 0.7975。

实测分数分布呈窄带特征：任何含"索引"的输入在 20 个锚点中有 11~15 个得分 ≥0.7，中位数 0.702~0.735。阈值 0.8 落在该窄带内部，判定对 0.00x 级差异极敏感。

## Goals / Non-Goals

**Goals:**

- 让"清理索引"及其同族口语表达稳定命中 `rebuild_index`，且判定余量充足（≥0.08）。
- 保持负样本（询问、无关文本）在阈值以下。
- 明确一条可复用的扩词准则，避免后续在已覆盖语义族上反复堆变体。

**Non-Goals:**

- 不调整阈值、模型、匹配器实现、归一化与疑问句拦截规则。
- 不去重既有同义锚点，不拆分"语义专属短语组"。
- 不新增命令，不改变 `rebuild_index` 的行为与回复文案。

## Decisions

### D1: 补锚点而非下调阈值

| 方案 | 结果 | 代价 |
|------|------|------|
| 阈值 0.8 → 0.78 | "清理索引"(0.7975) 命中 | "索引是什么"(0.7814) 同时命中 `index_report`，且疑问拦截拦不住（不含"吗/状态/多少"）；"清理无效索引"(0.7034) 仍 miss |
| 阈值 0.8 → 0.75 | 部分"清理"句命中 | `清理无效索引` 0.7034、`清理失效索引` 0.7337 仍 miss；负样本池进一步被侵入 |
| 新增锚点"清理索引" | 整族 9 条变体升至 0.88~1.00 | 目录多一条数据 |

阈值已是偏松侧（裸词"索引"0.8605 即命中），无下调空间；补锚点是唯一同时提升召回且不伤精确率的选项。

### D2: 只补一个锚点，不补同族变体

新增 `清理索引` 后的实测：

| 输入 | 原最高分 | 新增后最高分 |
|------|----------|--------------|
| 清理索引 | 0.7975 | 1.0000 |
| 索引清理 | 0.7974 | 0.9823 |
| 清理一下索引 | 0.7888 | 0.9263 |
| 帮我清理索引 | 0.7811 | 0.9209 |
| 清除索引 | 0.7932 | 0.9197 |
| 清理失效索引 | 0.7337 | 0.9100 |
| 把索引清理干净 | 0.7554 | 0.9005 |
| 清理文件索引 | 0.8481 | 0.8942 |
| 清理索引数据 | 0.7757 | 0.8900 |
| 清理无效索引 | 0.7034 | 0.8822 |
| 索引是什么 | 0.7814 | 0.7814（仍 miss） |
| 索引在哪里 | 0.7705 | 0.7705（仍 miss） |

`max` 语义下，一个族心短语即可把整族抬进安全区；再补 `清理文件索引`（0.8942）或 `清理无效索引`（0.8822）属于同族变体，边际收益趋近 0，故不纳入。

### D3: 接受共用目录带来的子串副作用

目录共用是既定设计（不为语义匹配器单设短语组）。因此 `清理索引` 同时成为子串字面触发词。评估：该短语为完整动宾结构，`清理日志`、`清理数据`、`清理缓存`、`帮我清理一下缓存` 均不含它，误伤面可忽略；而"清理索引"在子串模式下命中 `rebuild_index` 符合用户预期。

### D4: 扩词准则

补"新语义族"的收益远大于补"同族变体"：

- 新增 `清理索引`（新语义族）→ 整族 9 条从 0.70~0.79 抬到 0.88~1.00。
- 新增"刷新索引"的第 N 种说法（同族变体）→ 最高分不变，收益≈0。

后续扩容应以"语义族是否缺席"为判据，而非"口语说法是否穷尽"。

## Risks / Trade-offs

- [新增锚点提高近义输入的命中面] → 只新增职责语义内的动宾短语；负样本实测仍 <0.8，且疑问句拦截继续生效。
- [跨命令边界抖动] → `检查索引`~`分析索引` 0.8140、`检查文件索引`~`分析文件索引` 0.8470 等跨命令高相似对仍存在；新增 `清理索引` 后该族对 `index_report` 的余量扩大到 0.21 以上，不加剧现有风险。
- [真机分值与离线实测漂移] → 模型与缓存均本地固定（`cache/`），分值可复现；语义 smoke 测试以真模型校验。

## Migration Plan

仅数据变更，随下次进程启动生效（短语在启动时一次性嵌入）。无数据迁移，无回滚脚本；如需回滚，移除该短语并重启即可。
